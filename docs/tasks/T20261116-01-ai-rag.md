## 验证结果与未解决事项

核对工作区差异及既有交接材料。旧独立 AI 服务实施计划描述早期架构，现以已提交代码为基线。

- 首批选重庆市商务委员会的行政法规及市政府规章栏目。公开 robots.txt 返回 404，两页行政法规列表和样本文本可访问。手动限量采集 13 条，正文与 DOCX 附件可保存，测试覆盖重复链接、附件 404、补采及重跑。
- Windows 采集工具使用 Python 3.14 标准构建、Playwright 1.65.2 和 Docling 2.150.1。HTML 与 DOCX 对照读取同一条例，前 12 条的顺序一致。重庆市商务委员会发布的一份文本型 PDF 抽取出 3 张表，在 4 个 CPU 线程、关闭 OCR 的转换探针中用时 48.85 秒，峰值工作集 1690.5 MiB。采集工具独立运行，样本转换数值不代表常驻后端资源开销。
- 本地 Compose 使用 MySQL 9.7 与持久化 Chroma，13 条语料发布，重复导入全部跳过。同源从 HTML 换为 DOCX 后保留同一文档 ID，修订 2 发布前返回原生效索引，成功后切换。重建容器后仍可读取原件和检索，API 混合检索命中《政务数据共享条例》第十四条并返回全文。Windows 自动化使用 Chroma 内存客户端，持久化由 Linux 容器验证。
- 检索试验使用 TEI CPU 的 `BAAI/bge-small-zh-v1.5` 和 `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`。13 条实际语料，6 个问题含 4 个正例，每模式 18 次请求。无答案例仍产生候选，回答时需判断依据是否充分。各策略按顺序测量，P95 包含可能的冷启动及测量顺序影响。

| 检索模式 | Recall@5 | MRR@5 | P95 |
| --- | ---: | ---: | ---: |
| 向量 | 0.50 | 0.333 | 2167.01 ms |
| 混合 | 0.75 | 0.750 | 206.33 ms |
| 混合加重排 | 0.75 | 0.750 | 2350.76 ms |

- 生产 Compose 默认采用本次评测的混合策略和单路 24 候选。重排维持可选，启用时默认最多 16 候选并按配置计时。生产规模、真实生成模型回答质量和并发延迟留待目标部署环境验证。
- 将官方已废止规章填写经核对的废止日期后，用其前三条作隔离对照。三种策略默认均排除该版本，显式包含失效内容时分别在第 4、2、2 位召回。知识库后台核对《政务数据共享条例》第十四条的候选、完整条文、原文高亮和父子块。故障测试覆盖双路不可用、单路降级、重排超时、关键词写入失败和旧索引保留。实际 MySQL 9.7 验证两张关键词表和三个外键，重复执行建表命令成功。
