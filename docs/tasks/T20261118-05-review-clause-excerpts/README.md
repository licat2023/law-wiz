# 风险报告原文与法条联调

## 用户需求依据

- R1，本次聊天。用户要求“每一条风险条目内上面应该有对应的原文”，并询问现有知识库收录了哪些法律、截图中的合同为何没有直接法律依据、应该用什么样的合同测试。
- R2，本次聊天附件。截图中的高风险条目有风险描述和来源标记，缺少逐条合同原文。

## 当前任务理解

新审查从合同正文选取每条风险对应的连续摘录，经核对后展示在该条风险描述上方。对于缺项风险，引用最相关的条款或空白位置，无法定位时明确显示。保留现有风险报告。核对本机审查实际使用的知识库和截图对应任务，提供可上传的虚构采购合同、适合测试法条引用的资料和步骤。

实施选择：原文摘录按合同正文计算偏移，模型改写的段落不可冒充原文；模板不作为法律依据。本次在独立测试中验证法条引用，开发知识库继续由管理员维护。

## 实施方案

1. 核对现有报告和知识库，定位原文缺失及无直接法条原因。
2. 要求审查模型提供一段直接相关的原文，校验内容并计算位置。在网页和 PDF 的风险分析上方呈现。
3. 用 [虚构采购合同](purchase-contract.txt) 做端到端验证，并核对《民法典》买卖合同部分的相关条文。

## 验证结果与未解决事项

- 截图对应报告包含七条模型推断，均无保存的原文或偏移，也无已绑定的法条或审查规则。
- 本机只有「本地演示知识库」。开发样本《会议室预约》《交付验收登记》均已索引，类型为模板。本机开发库没有正式法规。当前审查用合同开头 200 个字符检索，候选与风险有关时才能支持引用。
- 从 Git 归档执行前端依赖安装、lint、类型检查和生产构建，AI Ruff 检查与 11 个测试、Java 21 Maven 构建与 5 个测试均通过。
- 使用本机页面提交样本，六条风险均在说明前显示原文区域。三处摘录逐字匹配合同，另外三条涉及合同未约定的事项，显示未定位。用缺少摘录的旧版响应样例验证了兼容显示。核对了下载按钮获取的 PDF 文件内容和排版，自动化浏览器的本地保存步骤会取消普通对象 URL 下载。
- 独立测试向真实模型提供官方《民法典》第六百二十二条作为检索候选，验收风险同时带有该法条引用和可核对的合同原文。默认库的正式法条入库及检索需要在导入后验证。
