# 可信时间戳用公共 TSA 起步，自建 TSA 仅作离线兜底

## 背景与决策

需求要求"系统计算哈希值并添加**可信时间戳**后上链存证"。

**决策**：
1. 开发与演示阶段使用**公共免费 TSA**（RFC 3161 时间戳服务）获取真实可信时间戳。
2. **自建 TSA**（开源实现）仅作为**离线兜底**，且在文档与界面中**明确标注其不构成第三方可信时间戳**。
3. 时间戳来源抽象为接口，与签章通道同构。

## 理由

1. **"可信"来自信任锚的位置，而不是来自密码学**：自建 TSA 只解决"时间戳的格式与签发"，不解决"时间是否可信" —— 因为信任锚是本平台自己签发的证书，等于自己为自己作证，无法向第三方证明。
2. **成本与可行性**：公共免费 TSA 零成本、真实 RFC 3161 时间戳、可被第三方验证，完全满足一期与演示需求；其缺点是依赖外部网络且无 SLA，因此需要离线兜底。
3. **术语必须区分**：`CONTEXT.md` 已将「时间戳」与「可信时间戳」定义为两个不同的术语 —— 前者仅记录时刻，后者要求信任锚在平台之外。文档与界面不得混用。

## 被否决的替代方案

- **仅自建 TSA**：无法对外主张时间可信。
- **购买权威 TSA 服务**：存在成本，且一期不涉及存证，无需现在决策。
- **本地机器时间直接入库**：等价于自建 TSA 但连时间戳凭证都没有，最弱。

## 后果

- 存证证书中必须**分别标注**时间戳来源（第三方 TSA / 自建 TSA），便于第三方判断可采信程度。
- 若后期需要具备司法采信力的时间戳，触发条件为：出现真实取证需求、或需要与司法区块链对接。届时新开 ADR 决策 TSA 服务商选型。
