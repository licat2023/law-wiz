# 数据库采用 MySQL 9.7 LTS，而非 MySQL 8.0 或 9.0

## 背景与决策

项目最初在技术栈中写定 `MySQL 8`（随后文档中具体化为 `mysql:8.0` 镜像）。2026-09-13 复核时发现该版本**已于 2026-04-30 结束扩展支持（EOL）**，不再获得任何安全补丁。同时有人提出改用 MySQL 9.0。

**决策**：采用 **MySQL 9.7 LTS**（`mysql:9.7` 官方镜像），并**在同一份 DDL 上完成 9.7 的实测验证**。

## 理由

### 1. 为什么不是 9.0（这是本条 ADR 最重要的部分）

MySQL 自 2023 年起分为两条发布轨道：

| 轨道 | 发布节奏 | 支持期限 | 版本号 |
| --- | --- | --- | --- |
| **LTS** | 约每两年 | 5 年首要支持 + 3 年扩展支持（共约 8 年） | 8.4、9.7 |
| **创新版（Innovation）** | 每季度 | **仅支持到下一个季度版发布为止** | 8.1–8.3、9.0–9.6 |

**9.0 属于创新版**，是 9.x 系列的第一个季度版本，**早已被 9.1 取代并停止支持**。它的支持窗口以"季度"计，且**比已经 EOL 的 8.0 更短**。选 9.0 不是"用新版本"，而是"用一个没有安全更新的过渡版本"。

同理，9.1–9.6 也都已作废。**9.x 系列中唯一应当使用的是 9.7 LTS**（2026-04-21 GA，支持至 2034）。

### 2. 为什么不是继续用 8.0

| 版本 | 轨道 | 首要支持结束 | 扩展支持结束 | 状态 |
| --- | --- | --- | --- | --- |
| MySQL 8.0 | 旧分支（pre-LTS） | 2025-04-30 | **2026-04-30** | ⛔ **已 EOL**，无安全补丁、无 bugfix、不受理工单 |
| MySQL 8.4 | LTS | 2029-04-30 | 2032-04-30 | ✅ 支持中 |
| **MySQL 9.7** | **LTS** | **2031-04** | **2034-04** | ✅ **当前 LTS** |

8.0 的最后一个版本是 8.0.46（2026-04）。继续使用意味着**新披露的 CVE 在该代码库中不会被修复**。本项目虽然只是课程项目，但"技术栈文档里写着一个已停止维护的数据库版本"在评审中是可被指出的硬伤，且没有任何收益换取这个代价。

### 3. 为什么是 9.7 而不是 8.4

8.4 支持到 2032，9.7 支持到 2034，**两者都是 LTS，都满足需求**。选择 9.7 的理由是它与 8.4 同属"当前受支持版本"，且是更新的基线；本项目的 DDL 未使用任何 8.4 与 9.7 之间的差异特性，因此**迁移风险为零**。

### 4. 我们正好处在可以自由选择的时点

Oracle **不支持跨 LTS 的原地升级**（8.0 → 9.x 不被支持，必须先到 8.4）。但本项目**数据库尚未在任何环境落地**（DDL 只在临时容器里验证过），因此不存在升级路径问题 —— **现在定版本的成本为零**，这是最省事的时机。

## 被否决的替代方案

| 方案 | 否决理由 |
| --- | --- |
| **MySQL 9.0** | 创新版，已被 9.1 取代，**支持窗口以季度计且已过期**，比 8.0 更不适合使用 |
| **继续用 MySQL 8.0** | 已于 2026-04-30 EOL，无安全补丁；技术栈文档中出现 EOL 版本是评审硬伤 |
| **MySQL 8.4 LTS** | 技术上完全可行，支持到 2032。**这是本决策的合理次选**；若担心 9.x 生态兼容性可选它 |
| **PostgreSQL 17 + pgvector** | 之前已评估（见 [ADR-0004](0004-vector-store-abstraction.md)）。它会同时解决关系型与向量存储，但需要重写全部 DDL 与调整技术栈文档，而当前 MySQL 路线已实测可用，**改动收益不足以抵消成本**。若后期确需收敛数据库种类，再新开 ADR |

## 后果

- 技术栈文档（02）与数据库设计文档（04）中的 `MySQL 8` / `mysql:8.0` 全部改为 **`MySQL 9.7` / `mysql:9.7`**。
- 数据库设计文档 §6.4 增加一节 **MySQL 9.7 验证结果**，与 8.0 的验证结果并列，证明 DDL 在两个版本上均可执行。
- **Docker 镜像标签必须写明 `9.7`**，不得使用 `mysql:latest`（否则会被动跟随未来的创新版）。
- **不使用发行版仓库安装 MySQL**：存在已知缺陷（MySQL Bug #120315），`mysql-community.repo` 的更新会**静默禁用 8.4 LTS 仓库并启用 9.7 LTS 仓库**，导致常规软件包更新时数据库被换大版本。本项目使用固定标签的 Docker 镜像，天然规避该问题。
- 若日后需要原地升级，**必须按 LTS 逐级进行**（9.7 → 下一个 LTS），不支持跳级；降级在任何方向都不被支持，只能从备份恢复。
