# 《智法宝》技术栈

## 1. 说明

本文档确定《智法宝》AI 法律助手平台从需求设计、开发编码、测试验证、部署运维到项目协作全生命周期所采用的技术选型，覆盖用户管理、合同审查、AI 问答、区块链存证、电子合同签署、电子印章管理全部 7 大功能模块。以下各项均为已确认的落地选型，构成后续系统设计与开发的技术基线。

**两项阅读前提**：

1. **交付分期**：设计覆盖全部 7 个模块，实现按六期交付，**一期只实现 M1 用户管理、M2 合同智能审查、M3 法律 AI 问答**。本文档中属于后期阶段的技术（区块链、电子签章、印章管理）为**已定选型但尚未实现**。详见 [ADR-0002](adr/0002-phased-delivery-ai-first.md) 与 [03-概要设计](03-概要设计.md) §3.3。
2. **合规边界**：本文档中的合规相关表述以 §4.2《合规边界声明》为准，该节明确区分了"实际达到的能力"与"不宣称的事项"。

**多端技术路线**（一期只做 Web，小程序与安卓为后续移植，见 [ADR-0010](adr/0010-multi-client-strategy.md)）：

| 客户端 | 技术选型 | 分期 | 是否与 Web 共用代码 |

| 安卓 App | **Kotlin + Jetpack Compose** | P6 | ❌ **不共用** |

>
> **对 Web 端的约束**：Web 可以自由使用浏览器专属库，但**不得把浏览器行为写进接口契约**（如依赖 Cookie 自动携带、依赖 `Referer` 判断来源），否则小程序与安卓无法接入。

### 3.3 后端

| 技术 | 形态 | 用途 |
| --- | --- | --- |
| Python 3.14（**标准构建**） | 后端运行时 | 约束 `>=3.14,<3.15`。**不使用 free-threaded（无 GIL）构建** —— `chromadb` 等核心依赖在其上无法安装，且本项目为 I/O 密集型负载，free-threading 无收益。见 [ADR-0009](adr/0009-python-version-and-free-threading.md) |
| FastAPI | 后端主框架 | 实现 RESTful API、业务逻辑处理与权限认证，支撑全部 7 个模块 |
| Pydantic | 数据模型与校验 | 请求 / 响应模型定义；**同时是接口契约的唯一真源**，经 `/openapi.json` 导出供 Apifox 与接口文档使用 |
| SQLAlchemy + Alembic | ORM 与数据库迁移 | 封装 SQL 操作；以版本化迁移脚本管理表结构变更 |
| PyPDF2 / python-docx | 文件处理库 | 解析 PDF / Word 合同文件，提取文本内容 |
| cryptography | 密码学库 | 计算 SHA-256 哈希值；RSA-2048 签名与验签（国密 SM 系列列为后期扩展点，见 [ADR-0003](adr/0003-crypto-rsa-first-sm-later.md)） |
| Pillow / OpenCV | 图像处理库 | 处理扫描件、印章图片、签名图片，实现印章合成到指定位置 |
| PyJWT | 身份认证 | 生成**访问令牌**（JWT，短时效、无状态）；**刷新令牌**存于 Redis，可撤销 |
| FastAPI Docs | 接口文档 | 自动生成 OpenAPI 文档并支持在线调试 |
| uv | Python 依赖管理 | 项目级虚拟环境与依赖锁定（提交 `uv.lock`），克隆后 `uv sync` 即可复现环境 |

### 3.4 AI 能力

| 技术 | 形态 | 用途 |
| --- | --- | --- |
| DeepSeek API | 大语言模型 | 合同风险分析、法律问答、AI 合同起草；经 OpenAI 兼容接口 / LangChain 接入 |
| LangChain | RAG 应用框架 | 串联知识库检索、prompt 组装、LLM 生成，降低 AI 幻觉 |
| Chroma | 向量数据库 | 存储法律法规、司法解释、合同范本向量，实现语义相似度检索 |
| **云端 OCR API** | **主用文字识别** | 识别图片 / 扫描件合同文字；**服务器不部署本地 OCR**（内存不足，见 §3.9 约束） |
| 百度 OCR | 云端 OCR 候选 | 具体服务商待定 |
| PaddleOCR（本地） | **后续扩展点** | 本地/离线场景备选，**一期不在服务器运行**；二期可部署在开发机 |
| Tesseract | 离线兜底 | 无网络或离线场景下的最后兜底方案；中文精度有限 |
| ModelScope / Hugging Face | 开源模型平台 | 下载开源词嵌入模型，用于本地化向量构建 |
| Ollama | 本地模型运行时 | 后期离线场景下自托管开源大模型，作为 DeepSeek API 的可替换实现 |

> **OCR 选型**：**一期使用云端 OCR API**（服务商待定），PaddleOCR 与 Tesseract 为后续扩展与兜底。调用集中在一处，不散落到各切片（见 [ADR-0012](adr/0012-defer-capability-abstraction.md)）。
>
> ⛔ **后端红线**：`requirements` / `pyproject` **不得引入 `paddlepaddle`、`torch`、`paddleocr`** —— 服务器可用内存仅约 700 MiB，而本地 OCR 运行时需 1.2–2 GB，容器启动即被 OOM Killer 静默杀掉。
>
> **文本型文件不走 OCR**：PDF / DOCX 中已含文本时直接解析，仅在图片与扫描件场景调用 OCR —— 对已含文本的文件做 OCR 只会引入识别误差（见 [03-概要设计](03-概要设计.md) §5.1）。
>
> **向量存储**：Chroma 经 `VectorStore` 接口接入，保留 `pgvector` / Milvus 作为备选实现（见 [ADR-0004](adr/0004-vector-store-abstraction.md)）。**Chroma 以进程内方式随后端启动，不单独起容器**，以节省服务器内存。

### 3.5 区块链存证

| 技术 | 形态 | 用途 |
| --- | --- | --- |
| FISCO BCOS | 联盟链底层平台 | 提供区块链网络环境，部署存证合约，实现哈希值上链与交易查询 |
| Solidity + Remix IDE | 智能合约开发 | 编写、编译、部署存证智能合约，实现哈希值、时间戳、元数据链上存储 |
| Web3.py | 区块链 SDK | 后端对接链上节点，调用合约发起上链交易、查询交易状态 |
| 公共 TSA（RFC 3161） | 可信时间源 | 获取**可信时间戳**：信任锚在平台之外，可被第三方验证 |
| 自建 TSA（开源实现） | 离线兜底时间源 | 无外网时的兜底；**签发结果不构成第三方可信时间戳**，须在界面与证书中明确标注来源 |

> **时间戳与可信时间戳是两个不同的概念**（见 [CONTEXT.md](../CONTEXT.md)）：本平台自行生成的时间戳只能证明"本平台在此时记录了它"，不能向第三方证明该时刻的真实性。时间戳来源在 **P2** 接入，存证证书中须**分别标注**来源类型（见 [ADR-0006](adr/0006-timestamp-source.md)）。

### 3.6 电子签章与身份认证

| 技术 | 形态 | 用途 |
| --- | --- | --- |
| 第三方电子签章服务（开发者版） | 签章服务 | 由**具备资质的服务商**生成可靠电子签名 / 电子印章，在合同指定位置签章，输出已签署 PDF；**法律效力由服务商承担**（见 [ADR-0005](adr/0005-signature-provider-abstraction.md)） |
| pyHanko + 自建 CA | 开源签章通道 | 后期可选实现：本地签章、零成本、可离线。**仅能证明文档完整性与签名时刻，不能证明签名人身份**，对外不得声称与手写签名同等法律效力 |
| 阿里云短信 / 腾讯云短信 | 短信验证码 | 发送登录、签署身份验证短信；开发环境以邮件或本地校验码替代 |
| 人脸识别服务 | 生物识别 | 实名认证，验证签署人本人身份 |
| 银行卡四要素验证接口 | 身份核验 | 校验姓名、身份证号、手机号、银行卡号一致性 |

> **法律效力边界**：本平台**不自行签发证书**。可靠电子签名能力由具备资质的第三方电子签章服务提供，平台负责签署流程编排、签署位置定位与结果存证。依据《电子签名法》第十四条，**可靠电子签名**与手写签名或盖章具有同等法律效力 —— 效力来源是服务商的 CA 证书，不是平台自身。
>
> **不可自建的能力**：短信通道、人脸识别、银行卡四要素验证均依赖运营商或持牌机构，无法以开源方案替代，只能"接第三方"或"降级"（如开发环境不发送真实短信）。
>
> **国家网络身份认证公共服务**：接入需机构资质，个人与课程项目无法申请；且它解决的是**身份核验**而非**电子签名**。列为后期可选身份核验通道，本期不实现。
>
> 签章能力在 **P3** 接入，本期（P1）不实现。

| 技术 | 形态 | 用途 |
| --- | --- | --- |

| 技术 | 形态 | 用途 |
| --- | --- | --- |
| Debian 13 (trixie) | 服务器操作系统 | 部署后端服务、数据库、区块链节点（实测环境） |
| Docker Compose | 容器编排 | 一键拉起前后端、数据库、向量库、区块链节点，环境统一；**每个容器须设内存上限** |
| OpenResty（1Panel 自带） | Web 服务器 / 反向代理 | 托管前端静态资源，反向代理后端接口，实现 HTTPS；**服务器 80/443 已被其占用，复用而不另起 Nginx** |
| GitHub Actions | CI/CD | 代码提交后自动构建、测试、部署 |
| 1Panel | 服务器运维面板 | Docker 容器编排与站点管理；目标主机已部署 |

| ELK Stack | 日志管理 | **后期可选**：日志收集与分析 |

> **部署主机**：单台 1Panel 主机，具备 Docker 编排能力。**单机资源有限，因此不引入 Kubernetes、消息队列集群、ELK 等重型组件** —— 它们会使单机资源不可承受，且对课程规模无收益。
>
> ⚠️ **实测资源约束（2026-09-13）**：服务器为 **2 vCPU / 1.7 GiB 内存（可用约 700 MiB）/ 24 GB 可用磁盘 / 8 GB swap**，且已运行禅道（内含 MariaDB，占用 434 MiB 常驻内存）。由此产生三条硬性约束：
> 1. **OCR 走云端 API**，不在服务器本地运行（本地 OCR 需 1.2–2 GB 内存）；后端依赖**不得引入 `paddlepaddle` / `torch`**，否则容器启动即被 OOM Killer 杀掉。
> 2. **每个容器必须设内存上限**（后端与 MySQL 各 384 MB、Redis 96 MB、MinIO 256 MB），超出应让容器自身重启，而不是拖垮同机的禅道。
> 3. **区块链只能用单节点**（4 节点需 8–12 GB 磁盘与 2–4 GB 内存）。

## 4. 选型原则与基线

### 4.1 选型原则

- **聚焦落地**：同一能力只保留一个默认实现，避免多选并列带来的实现分歧；备选项必须挂在接口之后，不得并列使用。
- **AI 生态一致**：后端 FastAPI 与 LangChain、DeepSeek API、Chroma 同处 Python 生态，AI 链路集成成本最低。
- **外部能力可替换，但不预建接口体系**：大模型、OCR、向量存储、签章、时间戳、区块链六类能力**只在一处封装**；一期不建 Provider 接口（见 [ADR-0012](adr/0012-defer-capability-abstraction.md)），出现第二种实现时再抽。
- **优先开源与自托管，但受资源约束**：时间戳优先公共 TSA；签章与实名认证等**依赖资质、无法自建**的能力才使用第三方服务。**OCR 是资源约束下的例外**——本地 OCR 运行时需 1.2–2 GB 内存，超出服务器可用内存（§3.9），故一期走云端 API；本地 PaddleOCR 与 Tesseract 作为后续扩展与离线兜底。
- **一键部署**：以 Docker Compose 统一开发与生产环境，降低课程项目的部署复杂度。
- **低成本可扩展**：优先选用开源方案与云服务免费额度，且支持后续替换（如 LLM、向量库、区块链平台可平滑切换）。

| 事项 | 本项目实际达到 | 不宣称 |
| --- | --- | --- |
| 电子签章 | 通过具备资质的第三方签章服务提供**可靠电子签名**，依据《电子签名法》第十四条具有与手写签名或盖章同等的法律效力 | 不对 **GB/T 38540-2020** 作合规声明 —— 该标准的合规性依赖经商用密码产品认证的密码模块，非"使用国密算法"即可达成（见 [ADR-0003](adr/0003-crypto-rsa-first-sm-later.md)） |
| 电子印章 | 印章的全生命周期管理**参照**《电子印章管理办法》（国办发〔2025〕33 号）的原则设计 | 不宣称本平台为电子印章的法定制作或认证机构 |
| 区块链存证 | 文件哈希与可信时间戳上链，可验证文件自存证后未被篡改 | 不宣称存证等同于**公证**，也不对文件内容的真实性、合法性作出判断 |
| 可信时间戳 | 由公共 TSA（RFC 3161）签发，信任锚在平台之外 | 不宣称自建 TSA 签发的时间戳具备第三方可信性 |
| 身份核验 | 接入第三方实名认证通道完成核验 | 不宣称接入**国家网络身份认证公共服务**（需机构资质） |
